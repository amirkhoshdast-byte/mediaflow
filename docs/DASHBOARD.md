## ۱. هدف داشبورد (یک جمله)

> مدیر حساب در **۳۰ ثانیه** بفهمد: چه چیزی مهم است، چه پیش‌نویسی منتظر **تصمیم** اوست (پرریسک‌ها اول)، و همان‌جا تأیید کند یا ویرایش کند.

هر چیزی که به این سه کار کمک نکند، از صفحه‌ی اول برداشته می‌شود.

## ۲. مشکل امروز (صادقانه)

صفحه‌ی اول چهار لایه‌ی هم‌وزن دارد و هیچ‌کدام «تصمیم» را جلو نمی‌اندازد:

1. نوار بالا با **۸ دکمه** (گزارش‌ها، منابع، خطوط قرمز، مدیریت، اعلان‌ها، تم، خروج ...) و ساعت و سه شمارنده.
2. **نوار مرور هوشمند** (شمارنده‌ها + دو فهرست).
3. **سه ستون** هم‌ارزش: رصد، استودیو، صف.
4. شش صفحه‌ی جانبی جدا.

نتیجه: همان سیگنال در سه جا دیده می‌شود (مرور هوشمند، ستون رصد، گزارش)، پیش‌نویس‌های یک تولید هم در استودیو و هم در صف تکرار می‌شوند، و «چه چیزی منتظر من است؟» جایی یک‌جا نیست. در موبایل سه ستون به سه تب تبدیل می‌شود، یعنی کار اصلی (تأیید) پشت دو کلیک است.

## ۳. ساختار پیشنهادی (معماری اطلاعات)

**پنج بخش، نه پانزده دکمه.** ناوبری اصلی فقط این‌هاست؛ همه‌ی تنظیمات پشت یک منو.

```
 ┌──────────────────────────────────────────────────────────────────┐
 │ اتاق فرمان روایت   [امروز] [پیش‌نویس‌ها] [رصد] [گزارش‌ها]   🔔  ⚙ مدیر │
 └──────────────────────────────────────────────────────────────────┘
   ⚙ منو: خطوط قرمز · منابع · کاربران · ممیزی · تم · خروج
```

| بخش | سؤالی که جواب می‌دهد | محتوا |
| --- | --- | --- |
| **امروز** (صفحه‌ی اول) | الان چه کاری از من می‌خواهند؟ | «منتظر تصمیم شما» + «مهم‌ترین‌های امروز» + نوار وضعیت |
| **پیش‌نویس‌ها** | همه‌ی پیش‌نویس‌ها در چه حالی‌اند؟ | تب‌ها + ویرایشگر کنار صفحه |
| **رصد** | چه خبرهایی آمده و منابع سالم‌اند؟ | فهرست سیگنال‌ها + افزودن خبر + سلامت منابع |
| **گزارش‌ها** | ۸ صبح و ۱۶ چه بود؟ | فهرست و صفحه‌ی گزارش |
| **تنظیمات** (منو) | منابع، خط قرمز، کاربران چگونه‌اند؟ | همان صفحه‌های امروز، فقط زیر منو |

### صفحه‌ی «امروز» (دسکتاپ)

```
 ┌─ نوار وضعیت: پست ۱/۳ · ریپلای ۰/۵ · پرریسک باز ۲ · منابع سالم ۱۴/۱۶ ──────────┐
 │                                                                              │
 │ منتظر تصمیم شما (۵)                         │ مهم‌ترین‌های امروز                │
 │ ┌───────────────────────────────────────┐   │  1. عنوان … [سبز] [ارتباط ۹۰]   │
 │ │ ⚠ پرریسک · برخورد با خط قرمز: …       │   │     [پیش‌نویس بساز]               │
 │ │ متن پیش‌نویس (قابل ویرایش در جا)       │   │  2. عنوان … [روایت و پاسخ]       │
 │ │ لحن ۷۴ · ۲ مغایرت       [تأیید] [ویرایش]│   │  …                               │
 │ └───────────────────────────────────────┘   │                                   │
 │  (پرریسک‌ها اول، بعد خودکارها، بعد بقیه)     │                                   │
 └──────────────────────────────────────────────────────────────────────────────┘
```

- **ستون راست (عریض): «منتظر تصمیم شما».** هر کارت: متن، دلیل پرریسک، خلاصه‌ی بررسی لحن، ویرایش در جا، دکمه‌ی «تأیید انتشار» و «رد». این **تنها** جایی است که تصمیم گرفته می‌شود.
- **ستون چپ: «مهم‌ترین‌های امروز».** هر ردیف یک دکمه‌ی «پیش‌نویس بساز».
- **موبایل:** همان دو بخش زیر هم، نوار پایینی با ۴ آیکن (امروز، پیش‌نویس‌ها، رصد، گزارش‌ها).

### صفحه‌ی «پیش‌نویس‌ها»
تب‌ها: **همه · ⚠ پرریسک · پیشنهاد خودکار · تأییدشده · منتشرشده**. فهرست در یک ستون، ویرایشگر/استودیو به‌صورت **کشوی کناری** (نه ستون جدا). «پیشنهاد جدید» دکمه‌ی بالای صفحه است (موضوع یا سیگنال، قالب، زبان).

### صفحه‌ی «رصد»
جدول/فهرست سیگنال‌ها با فیلتر (منطقه، دسته، امتیاز، منبع، تاریخ)، جست‌وجو، «افزودن خبر/توییت» بالا. کنارش یک نوار «سلامت منابع» (با پیوند به مدیریت منابع).

## ۵. جریان‌های کاربر

1. **صبح (۳۰ ثانیه):** باز کردن «امروز» ← نوار وضعیت ← «منتظر تصمیم» (پرریسک‌ها اول) ← تأیید یا ویرایش ← مرور «مهم‌ترین‌ها».
2. **از خبر تا انتشار:** سیگنال مهم ← (خودکار یا دستی) ۳ پیش‌نویس ← بررسی لحن خودکار ← تأیید ← انتشار دستی در X ← «ثبت انتشار».
3. **پرریسک:** برچسب و دلیل ← خواندن مغایرت‌ها ← ویرایش یا «اعمال پیشنهاد» ← تأیید با پرسش صریح.
4. **نگهداری هفتگی:** منابع (خطاها)، خطوط قرمز، کاربران.

## ۷. الزامات غیرکارکردی

- **راست‌به‌چپ کامل**، ویژگی‌های CSS منطقی، تاریخ شمسی اصلی، میلادی فرعی.
- **دسترسی‌پذیری:** ناوبری با صفحه‌کلید، فوکوس دیدنی، کنتراست ≥ ۴٫۵، احترام به `prefers-reduced-motion`.
- **سرعت:** صفحه‌ی «امروز» کمتر از ۲ ثانیه؛ اجرای طولانی (تولید) با نشانگر پیشرفت.
- **موبایل اول برای تأیید:** تأیید یک پیش‌نویس از موبایل حداکثر در ۲ لمس.
- **حالت‌ها:** هر ویجت خالی، در حال بارگذاری و خطا دارد (پیام روشن، نه صفحه‌ی خالی).
- **امنیت:** هیچ کلید یا رازی در رابط نمایش داده نمی‌شود؛ ممیزی روی رویدادهای حساس.

## ۸. طرح اجرا (بعد از تأیید شما)

1. **گام ۱ (P0، حدود یک دور کار):** ناوبری ساده + صفحه‌ی «امروز» + «پیش‌نویس‌ها» با کشو؛ حذف ستون‌های تکراری؛ تست Playwright برای جریان صبح.
2. **گام ۲ (P0 زیرساخت):** استقرار روی سرور، TLS، پشتیبان‌گیری.
3. **گام ۳ (P1):** صفحه‌ی رصد کامل، موبایل، ممیزی، CI، پایش سلامت.
4. **گام ۴ (P2):** اعلان ایمیل/تلگرام، PWA، فیلترهای ذخیره‌شده.

## ۹. تصمیم‌هایی که از شما می‌خواهم

1. **ساختار پنج‌بخشی** (امروز، پیش‌نویس‌ها، رصد، گزارش‌ها، تنظیمات در منو) را تأیید می‌کنید؟
2. **«منتظر تصمیم شما»** به‌عنوان قلب صفحه‌ی اول (پرریسک‌ها اول): درست است؟
3. استودیو به‌جای ستون، **کشوی کناری** شود؟
4. فیچرهای P0 این فهرست درست‌اند؟ چیزی هست که باید P0 شود یا حذف شود؟
5. **سرور:** برای استقرار (F-81) سرور دارید (VPS در کدام کشور/ارائه‌دهنده)، یا باید پیشنهاد بدهم؟ توجه: سرور باید به اینترنت آزاد دسترسی داشته باشد (Anthropic، منابع خبری).
6. اعلان ایمیل یا تلگرام را می‌خواهید (F-53)؟
